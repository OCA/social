This module adds the **email** channel to *Mail Message Import*
(``mail_message_import``): the senders write or forward their emails to
a receiving address, and each email becomes a received message,
identified, grouped and processed as the messages of every other
channel.

- A **receiving channel** of type *Email* has a receiving address and
  the incoming mail server of Odoo that reads its mailbox.
- The **authorized addresses** of type *Email* are compared normalized:
  without the name nor the capital letters.
- Each email is a **received message** of type *Email*, with its
  subject, its headers and body as text, its attachments as files and
  the email itself in its chatter.

Configuration
=============

1. Create in your mail server a mailbox only for this channel, e.g.
   ``orders@company.com``. Nothing else may read it: the incoming mail
   server marks the emails as read. The catchall or a mailbox already
   read by another route of Odoo (CRM, helpdesk...) does not work: the
   emails would go there.
2. In *Message Import > Configuration > Receiving channels*, create a
   channel:

   - *Channel*: **Email**.
   - *Receiving address*: the address of the mailbox.
   - *Configure the incoming mail server* (administrators only) opens
     the incoming mail server form of Odoo with the user, IMAP over SSL,
     the port 993, *Create a new record* set to *Received Message* and
     *Keep attachments*, and links the server to the channel. Fill in
     the server and the password, press *Test & Confirm* and keep the
     server active.
   - A server created in *Settings > Technical > Incoming Mail Servers*
     works too, if it creates *Received Message* records.

3. In each sender, tab *Phones and email addresses*, add the email
   addresses it sends from, with the channel *Email*. A new address can
   also be authorized from its first email, in *Message Import > To
   review > Unknown senders*.

The channel is *Pending verification* while its incoming mail server is
not confirmed or is archived: no email is read until then.

Odoo does not check who sends an email: the *From* can be forged. Let
the mail server filter the emails with the SPF, DKIM and DMARC of the
domains.

Usage
=====

- The emails appear in *Message Import > Received > Received messages*
  with the type *Email* and their subject. The filter *Email* shows only
  them.
- Each email is one message: an email that arrives twice (same
  ``Message-Id``) is received once.
- Every email that reaches the mailbox is a message of the channel, even
  when it replies to a document of Odoo or is also sent to an alias.
- A reply to a received email is a new message of the conversation, not
  a note on the previous one: it is how the senders correct what they
  sent.
- The files of a message are the attachments of the email, except the
  images smaller than 20 KB (logos and icons of the signatures) and the
  copy of the original email. The forwarded emails (``.eml``, ``.msg``)
  are unpacked as in the other channels.
- The module sends no email.
