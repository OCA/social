This module stores the ids of the records involved in tracked changes of
many2many and one2many fields.

Odoo tracks these fields, but it only keeps the names of the records,
joined by commas, in ``old_value_char`` and ``new_value_char``. With
this module, the ids before and after the change are also stored as a
JSON list in ``old_value_text`` and ``new_value_text`` of
``mail.tracking.value`` (``"[]"`` when there is no record). The names
stay as Odoo stores them.

The ids make it possible to know which records were added or removed
even when two records have the same name, or when a record is renamed or
archived later.

It depends on Odoo's *Discuss Tracking* (``mail_tracking``) technical
module, which stores the tracking values and shows them in Settings ›
Technical › Discuss › Tracking Values (this replaces the menu the module
had up to 16.0).

Use Cases / Context
===================

Up to 16.0 this module added the tracking of many2many and one2many
fields. Since 17.0, Odoo tracks them natively, so the module was not
migrated (`#1359 <https://github.com/OCA/social/pull/1359>`__,
`#1465 <https://github.com/OCA/social/pull/1465>`__,
`#1466 <https://github.com/OCA/social/pull/1466>`__). Odoo only stores
the names of the records, though, so this module now keeps the part that
Odoo does not cover: the ids.

Usage
=====

Read the ids of the tracked changes of any tracked many2many or one2many
field, for example the tags of the applicants (``hr_recruitment``):

.. code:: python

   field = env["ir.model.fields"]._get("hr.applicant", "categ_ids")
   env["mail.tracking.value"].search_read(
       [("field_id", "=", field.id)],
       ["old_value_char", "new_value_char", "old_value_text", "new_value_text"],
   )
   # [{'old_value_char': 'Tag A', 'new_value_char': 'Tag A, Tag B',
   #   'old_value_text': '[1]', 'new_value_text': '[1, 2]', ...}]

``json.loads()`` turns ``old_value_text`` and ``new_value_text`` into
lists of ids.
